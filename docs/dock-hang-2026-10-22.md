# CalDigit dock incident and network-context hotfix — 2026-10-22

The user reports that connecting the CalDigit TS5 Plus froze the menu-bar clock
and required a forced reboot. They confirmed the 09:18 reboot, before the final
0.1.6 install. The incident therefore occurred with 0.1.5 build 8. The CalDigit
remains connected during this investigation; no live reconnect, interface toggle,
share eject, credential change, or firmware change was performed.

## Evidence

- At 09:14:43–09:14:49, the prior boot recorded repeated display reconfiguration.
  WindowServer logged synchronization timeouts at 09:14:49 and a fence timeout at
  09:15:16. These do not identify which component caused the display stall.
- At 09:15:03, the installed Tweaks 0.1.5 build 8 crashed with
  `EXC_BREAKPOINT / SIGTRAP`. Thread 5 was `SCDynamicStore notifications`.
  The matching UUID in the retained 0.1.5 dSYM symbolized the app frame to
  `@objc closure #2 in ShareConnectivityWatcher.start()`, line 466: the context
  release callback. Its stack was `__SCDynamicStoreDeallocate` → the app callback
  → Swift executor check → libdispatch queue assertion.
- The main thread was in the normal AppKit event loop at the crash. This proves
  a Tweaks callback defect, not that Tweaks caused the preceding WindowServer
  stall or the entire machine freeze. No matching kernel panic report or retained
  pre-reboot kernel records were available in the inspected diagnostics.
- The same lifetime callbacks were present in 0.1.6. Its prior cancellation/status
  fixes did not repair this defect.

Raw diagnostics and preference snapshots are private ignored files under
`.build/dock-hang-20261022/`; they are not release assets or repository content.

## Full-freeze follow-up

The lid was closed. The Dell U3824DW uses the TS5 Plus built-in DisplayPort;
the LG SDQHD uses the USB-C-to-DisplayPort cable identified by the user as
[Amazon ASIN B074V5MMCH](https://www.amazon.com/dp/B074V5MMCH). The exact cable
revision and dock socket were not physically inspected. Conflicting reseller
specifications do not establish the installed cable's capabilities or a defect.

The current read-only inventory reports an M5 Max on macOS 27.0.1 (26A434),
Dell 3840 × 1600 at 60 Hz and LG 2560 × 2880 at 60 Hz, extended. Dock firmware
is 71.1, matching CalDigit's latest published version when checked on October 22.
CalDigit describes that version as improving monitor and USB stability;
there is no newer published firmware to apply from that source.
[Official firmware reference](https://www.caldigit.com/ts5-plus-and-element-5-hub-macos-firmware-update-procedures/).
The manual supports two displays on compatible Macs and DisplayPort adapters on
the spare Thunderbolt ports. This supports the general topology, not acceptance
of this particular cable or a data-only USB-C socket.
[Official manual](https://downloads.caldigit.com/TS5Plus/CalDigit_TS5_Plus_Manual_EN.pdf).

The expanded collection retained 292,469 records from the incident boot within
09:14:35–09:16:30 CDT. Actual retained coverage is 09:14:41.801–09:16:29.929.
Absolute epoch bounds were used for `log show`, then boot identity and timestamps
were checked in the returned JSON. A direct `bootUUID` predicate returned no
records despite that boot being present; that empty query is not absence evidence.

The first reply timeouts precede the LG's appearance/disappearance sequence.
Neither those recipients nor the LG cable can be assigned responsibility from
this ordering. The later fence timeout and Bluetooth watchdog make a broader
wake/display/service incident the stronger working lead than a continuously
running Tweaks callback sustaining the freeze. They do not exclude an earlier
Tweaks trigger or prove a shared cause between the graphics and Bluetooth faults.

Symbolizing the graphics warning sites resolves to
`CA::Render::Context::check_sync_reqs(double)` and
`CA::Render::Fence::ftimeout_callback(double, void*)`. These are single warning
sites, not blocked-thread stacks or proof of which client owns the context.
WindowServer emits records through 09:15:53; other processes continue through
09:16:29. Background activity is compatible with the reported frozen graphical
session and does not establish whether the kernel hung later. No retained kernel
entries, matching panic, explicit GPU/DCP panic or event-tap timeout was found in
this window. Missing retained evidence cannot rule those causes out.

Three-second current samples show Tweaks and Control Center main threads idle in
their run loops. Current WindowServer sampling is protected and was unavailable
without administrator authentication. No password prompt was requested: a healthy
current stack cannot reconstruct the earlier stall.

## App paths still worth hardening

Read-only source review found synchronous global input/display paths that deserve
separate work, but no incident evidence establishes them as the cause:

- Green-button handling uses a session event tap on main, synchronous window-list
  discovery and AX calls before returning a click. Per-call AX timeouts do not
  bound the entire callback, and timeout disablement immediately re-enables it.
- Away dimming writes built-in brightness and external gamma after screen changes
  while dimmed, and restores ColorSync synchronously. Normal resume resets the
  two-minute idle threshold. The fresh Away assertion does not establish that
  dimming ran during the six seconds before the synchronize timeouts.
- CoreAudio discovery/listener work on main can stall Tweaks if driver IPC stalls.
  No blocked driver stack was retained here.

Automatic window layouts were disabled in the captured preferences. No global
display capture, display-configuration transaction, or registered CoreGraphics
display-reconfiguration callback was found in Tweaks. The existing main-thread
run-loop crash stack cannot prove that earlier input/display work never blocked.

## Prepared capture and next evidence

`scripts/capture-dock-diagnostics.py` is a manually invoked, read-only collector.
It records current display/Thunderbolt inventory, power assertions, preference
snapshots, filtered logs and short samples of the installed Tweaks, Control Center
and WindowServer. It never reconnects a device, launches/quits an app, changes
preferences or network state, requests authentication, uploads data or schedules
another run. Run it as the logged-in user, never with sudo.

```sh
python3 scripts/capture-dock-diagnostics.py --seconds 120
```

The recording phase accepts 1–300 seconds. Inventory and final snapshots have
separate bounded command deadlines; sampling shares the recording deadline.
The log stream also has a native backup timeout one second beyond the requested
recording duration. Ctrl-C/SIGTERM stops owned child process groups and retains an
incomplete manifest. Existing output directories are rejected. Output defaults to
a new mode-0700 folder under `~/Code Support/Tweaks/diagnostics/`; raw logs and
preference files are private and must not be committed or shared automatically.
Exit 0 means every requested command succeeded and preference keys matched;
exit 1 marks partial/unavailable evidence or changed/unreadable preferences;
exit 130 marks cancellation. Protected WindowServer sampling remains explicitly
unavailable at the current user's permissions. The collector does not capture
protected blocked-thread stacks or establish historical causality.

Only stable-session captures and cancellation checks were performed. No physical
reconnect is authorized yet. A later explicitly authorized comparison should
capture contemporaneous blocked stacks, compare the same connection with Tweaks
quit while preserving preferences, then isolate the LG USB-C-to-DisplayPort path
one factor at a time. Protected WindowServer stacks require a separately approved
administrator capture. Do not infer a successful reconnect from stable samples.

Collector verification passed Python compilation and fixtures for bounded child
termination, missing commands, refusal to overwrite an output directory, repeated
cancellation during child creation, duplicate process names and an early successful
log-stream exit. The final stable-session recording stopped after 5.004 seconds;
the sole unavailable command was the protected WindowServer sample, correctly
reported as incomplete with exit 1. Live SIGTERM cancellation exited 130, reaped
both observed child process groups and retained the incomplete manifest. Independent
read-only review found no remaining collector blocker or causal overclaim.
The final preference export matches every pre-follow-up key and shortcut value;
both unrelated local handoff files retain their original hashes. Installed version,
build and source remain 0.1.7 / 10 / `7222203520a9631797798679c073bd3555bab331`.
This follow-up changes only the collector and documentation. App tests, benchmarks,
signing, installation and deployment were not repeated; their earlier hotfix
results are recorded below.

## Repair

0.1.7 build 10 moves the context retain/release functions outside `MainActor`.
SystemConfiguration's selected notification queue does not constrain the queue
used to destroy its context. A nonisolated immutable Sendable box now owns a
main-actor callback that captures the watcher weakly. Notifications hop to
MainActor, and session-generation checks reject delivery after stop/restart.
NWPath notifications use the same generation boundary. Existing saved preferences,
share choices, pause state, and shortcut assignments are not migrated or changed.

Regressions invoke the actual C context lifetime pointers on a background task,
verify balanced box deallocation, and verify background notifications deliver on
the main thread without retaining the watcher. They do not subscribe to live
network notifications or change network configuration.
