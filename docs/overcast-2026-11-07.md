# Send to Overcast — November 7, 2026

Version 0.1.11, build 14. Built on the existing 0.1.10 release, retaining its
quiet AppUpdater pin. This feature is part of Tweaks and its existing Finder
extension, rather than a separate installed app or Automator workflow.

## Use

Right-click one or more downloaded MP3/M4A files in Finder → Send to Overcast… →
review the selection → Upload to Overcast. The action is also in Files & Finder.
Sign in directly to Overcast in the window once. Its persistent WebKit store is
separate from Dia. Overcast's account subscription and storage limits apply.

The action accepts 1–20 files, each between 1 byte and 1,000,000,000 bytes. It
rejects directories, symlinks, unavailable files and dataless cloud placeholders.
Original audio stays unchanged. The website performs its normal upload and
registration; Tweaks does not implement an undocumented HTTP upload API.

## Boundaries

- A `tweaks://overcast` request only opens a review window. Upload needs a visible
  user action, because custom URL schemes can also be invoked by websites.
- File paths are encoded as URL query values. Parsing rejects unexpected fields,
  relative/NUL paths, non-audio, duplicate paths, credentials, ports and fragments.
- The native file chooser only delivers the current reviewed file to the main
  HTTPS `overcast.fm/uploads` frame after off-main identity revalidation.
- Credentials, cookies and signed server fields remain in WebKit. The code reads
  only upload-control readiness and rendered episode links.
- A new matching episode link confirms one upload. Existing/unrelated links and
  longer filename prefixes do not advance the batch. Unconfirmed transfers time
  out after 15 minutes per file. Failed/stopped selections cannot silently retry.
- Stop Upload replaces the page to stop further work; bytes accepted before
  cancellation may remain on the server. Review the list before reselecting.
- Active uploads hold quit/update guards. Logout/shutdown is still allowed.
- Web content is created for the manual action and released when its window
  closes. There is no added background poll or saved feature toggle.

  each. The XCTest host suppresses normal background tweak startup.

  request sends nothing, an explicit upload delivers the selected filename and
  exact bytes, sequential selection sends each file once, zero-byte files never

  rewrites its embedded media bundle on every invocation, and an incremental
