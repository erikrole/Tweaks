# Five new Tweaks features — 2026-10-12

Implemented locally on top of the earlier performance work, based on commit
`8f31d1a5ca1be1b2161e86fdf117085221e240fd`. All changes remain uncommitted.
No push, installation, signing, notarization, or deployment was performed.

## Behavior

| Feature | Where to use it | Safeguards and scope |
| --- | --- | --- |
| Saved window layouts | Windows and notifications; optional save/restore shortcuts | One saved layout per exact display UUID/geometry arrangement. Restores only uniquely matching, open standard windows. Requires Accessibility. |
| Per-device volume limits | Keyboard and sound | Rules keyed by Core Audio device UID. Never raises volume. Optional mute of the next output when switching away. Hardware-only controls are identified. |
| Quick Image Actions | Finder context menu or Finder section in Tweaks | Review up to 20 files; export JPEG, PNG, or HEIC at original size or a chosen longest edge. Metadata removal is on initially. Originals remain unchanged. |
| Safe eject | Sleep section or configurable shortcut | Checks all mounted volumes on a supported physical drive, lists blocking processes, revalidates identity/activity, and requests normal eject without force. |
| Duplicate-download review | Downloads and clipboard | Streaming SHA-256 finds candidates. Show Both, Keep Both, or explicitly Trash New Copy. Both file identities and every byte are checked again before trash. |

New automatic features start disabled. New shortcuts start unassigned. Existing
tweak preferences and defaults are preserved. Image export and manual eject are
explicit actions. Duplicate review is session-only; duplicate ZIP/invite copies
are left intact and bypass automatic extraction/import even after Keep Both.

## Implementation and review

- Layout capture/restore uses a dedicated utility queue, AX messaging timeouts,
  and cancellation on monitor changes or disabling the feature. Reconnect waits
  for canceled work to drain. Preferences contain window fingerprints rather than
  raw document paths/titles. It does not launch closed apps or infer ambiguous
  windows; changed title-only identities may not match.
- Audio limits use property listeners. Transient missing outputs retain the prior
  device identity for mute-on-switch behavior. Up to three downward corrections
  accommodate rounded hardware volume steps, with repeated-event suppression and
  actual readback/status. A driver that cannot meet the limit is reported.
- Image work runs off-main through ImageIO. Exports apply orientation once, resize
  without upscaling, flatten JPEG alpha onto white, and optionally discard metadata
  including GPS. Private staging directories protect in-progress files; published
  copies have mode 0600 and use atomic no-overwrite renames. Animated/multi-page,
  invalid, changed, and excessive original-size inputs fail without replacing a
  source. The Finder extension retains its read-only sandbox entitlement; its URL
  request only opens the host review panel.
- Safe eject resolves single-store APFS containers to physical disks, combining
  APFS and non-APFS siblings. Internal/root/image/virtual disks are excluded.
  Known pseudo filesystems are skipped; nullfs aliases join their backing disk's
  group. Unknown mounted disk mappings, unfamiliar filesystems, and unsupported
  multi-store arrangements stop inventory. Active render engines, open files, or
  unreadable open-file checks prevent ejection. A disk/configuration change after
  checking open files also prevents ejection. Normal Disk Arbitration remains the
  final arbiter if activity starts after inspection.
- Duplicate hashing uses bounded chunks and cancellation on the Downloads queue.
  Empty files, symlinks, hard links, incomplete downloads, and resource forks are
  excluded. Review is capped at 100 entries; files remain untouched when review is
  full. Identity checks reduce pathname races but do not create a transaction
  across an external process changing a file and the eventual Trash operation.
- Independent read-only review covered destructive file/device boundaries and
  audio feedback loops. The identified monitor, audio, APFS, and metadata issues
  were corrected and exercised by targeted fixtures where possible.

## Remaining acceptance

The XCTest host suppresses normal tweak startup. No real audio volume/mute changes,
window moves, drive ejections, or duplicate-download trash actions were performed.
The current installed app was not replaced. Signed Finder-to-host handoff,
Accessibility window behavior across reconnects, Bluetooth/USB audio transitions,
external multi-volume drive operations, and visual settings-panel acceptance still
need the updated installed build. Fixture exports establish encoded-image data
checks, not a visual color-quality review.

No new before/after performance claim is made for these five features. Existing
short app performance checks run with the suites; the long file-work profiles and
package benchmarks remain opt-in. The prior measured main-thread improvements are
in [file-work profiling](file-work-profile-2026-10-12.md). Duplicate hashing adds
disk I/O when enabled; its cost on a large real Downloads folder has not yet been
profiled.
